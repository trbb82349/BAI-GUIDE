# auto-update-site 쉽게 설명

## 이 스킬은 무엇을 해주나요?

"사람이 손대지 않아도 정해진 요일·시간마다 자동으로 내용이 새로 고쳐지는 웹사이트"를 만들어주는 도구입니다. 데이터를 자동으로 모으고, AI로 분석하고, 웹페이지를 새로 만들고, 인터넷에 공개하는 전체 과정을 무료 서비스만으로 구성합니다. china-trend-tracker 프로젝트가 바로 이 스킬로 만들어진 예시입니다.

## 언제 자동으로 켜지나요?

아래처럼 말하면 자동으로 켜집니다.

- "자동으로 업데이트되는 웹사이트 만들어줘"
- "주기적으로 데이터를 가져와서 보여주는 페이지 만들어줘"
- "매주/매일 자동 실행되는 사이트 만들어줘"
- "GitHub Pages에 자동 배포해줘"

## 이 스킬이 왜 필요한가요?

"자동 업데이트 웹사이트"는 여러 조각(데이터 수집, AI 분석, 웹페이지 생성, 예약 실행, 인터넷 공개)이 딱 맞게 맞물려야 작동합니다. 이 스킬은 그 조각들을 매번 처음부터 설계하는 대신, 이미 검증된 표준 구성(수집 코드 → 데이터 파일 → 웹페이지 생성 코드 → 예약 실행 → 자동 배포)을 그대로 가져다 쓰게 해줍니다. 덕분에 사람이 서버를 따로 빌리거나 켜둘 필요 없이, 완전히 무료로(GitHub이 제공하는 기능만으로) 자동화된 웹사이트를 운영할 수 있습니다.

## 이 스킬 안에 나오는 용어 쉽게 풀이

- **GitHub Actions**: GitHub이 무료로 제공하는 "정해진 시간에 코드를 대신 실행해주는 서비스". 내 컴퓨터를 켜두지 않아도, 예약해둔 시간(예: 매주 월·목요일 아침 9시)에 데이터 수집·분석·웹사이트 생성을 자동으로 해줍니다.
- **cron(크론) 스케줄**: "언제 자동 실행할지"를 정하는 표준 표기법. 예를 들어 "매주 월요일과 목요일 아침 9시"처럼 반복 주기를 지정합니다. 단, "9시 정각"처럼 시간을 딱 맞춰 예약하면 GitHub 서버가 몰리는 시간대라서 실행이 늦어지거나 그날은 아예 안 도는 경우가 실제로 있었습니다. 그래서 이 스킬은 "9시 13분"처럼 정각을 살짝 비켜서 예약합니다.
- **data.json**: 수집한 데이터를 저장해두는 파일. 여기에 "마지막으로 언제 업데이트됐는지" 정보도 함께 기록해둡니다.
- **collect.py**: 외부에서 데이터를 가져오고, 필요하면 AI에게 분석까지 시켜서 data.json을 최신 상태로 갱신하는 코드.
- **build_site.py**: data.json 안의 데이터를 읽어서, 사람이 보는 실제 웹페이지(HTML)로 바꿔주는 코드.
- **GitHub Pages**: GitHub 저장소 안의 파일을 인터넷 주소로 공개해주는 무료 호스팅 서비스. 별도로 서버를 빌릴 필요가 없습니다.
- **Gemini API**: 구글이 제공하는 무료 AI 분석 서비스. 수집한 데이터를 AI가 읽고 판단하게 할 때 씁니다.
- **Secrets(비밀 값 저장소)**: API 키 같은 민감한 값을 코드에 직접 적지 않고, GitHub 설정 안에 안전하게 등록해두는 공간.
- **cron-job.org**: "정해진 시각마다 대신 인터넷 요청을 보내주는" 무료 외부 서비스. GitHub의 자체 예약 실행이 가끔 안 도는 문제가 있어서, 이 서비스가 매일 정해진 시각에 "지금 실행해!"라는 신호를 GitHub에 대신 보내주도록 이중 안전장치를 만들어둡니다.
- **개인용 액세스 토큰(Personal Access Token)**: 외부 서비스(cron-job.org 등)가 내 GitHub 저장소의 "실행 버튼"을 대신 눌러도 된다고 허락해주는 열쇠 같은 값입니다. 비밀번호처럼 다뤄야 하고, 딱 그 저장소 하나에만, 딱 필요한 권한(여기서는 "자동 실행 관련 권한")만 주는 게 안전합니다.

## 사용할 때 알아두면 좋은 점

- 필요한 서비스(GitHub Actions, GitHub Pages, Gemini API, 네이버 API)는 모두 무료 사용량 안에서 운영되도록 설계돼 있지만, 사용량 한도(예: Gemini 하루 1,500회)는 넘지 않는지 확인이 필요합니다.
- `docs/` 폴더에 `.nojekyll`이라는 빈 파일을 꼭 넣어야 GitHub Pages가 정상적으로 작동합니다. 빠뜨리면 사이트가 404 오류로 안 뜰 수 있습니다.
- `data.json` 파일에는 `//` 같은 주석을 쓸 수 없습니다. 메모를 남기고 싶으면 `"_comment"`라는 이름의 항목을 따로 만들어야 합니다.
- 자동 실행 중 다른 변경사항과 저장 충돌이 나면, 최신 내용을 받아온 뒤 다시 시도하는 절차가 이미 포함돼 있습니다.
- 게시판처럼 "페이지를 넘겨가며 새 글만 가져오는" 수집 코드를 짤 때는 주의가 필요합니다. 어떤 소스를 처음 추가하면서 최근 글(1페이지)만 채워두고 시작했다면, 그다음 페이지들은 한 번도 확인해본 적이 없는 상태입니다. 이런 상태에서 "내가 이미 아는 글 목록에 없으면 새 글"이라고만 판단하면, 2페이지·3페이지의 옛날 글도 전부 "새 글"로 착각해서 몇 달 전 글까지 왕창 끌어올 수 있습니다. 실제로 이 스킬로 만든 프로젝트에서 이런 사고가 한 번 있었습니다 — "한 페이지 안에 이미 아는 글이 하나라도 있으면 그 페이지에서 멈춘다"는 규칙을 넣어야 안전합니다.
- 자동 업데이트가 안 되는 것 같으면, 저장소의 **Actions** 탭에서 최근 실행 기록(성공/실패, 마지막 실행 시각)부터 확인하면 원인을 좁힐 수 있습니다.
- GitHub의 자체 예약 실행(schedule)은 무료·개인 계정 저장소에서 며칠씩 통째로 안 도는 경우가 실제로 있었습니다. 이럴 땐 cron-job.org 같은 외부 서비스가 매일 정해진 시각에 대신 "지금 실행해!" 신호를 보내주도록 설정하면 훨씬 안정적입니다. 이 설정을 할 때 "401 Unauthorized" 오류가 뜬다면 거의 항상 토큰 값을 완전히 새로 안 바꾸고 예시 문구가 일부 남아있는 경우이니, 값 칸을 완전히 지우고 다시 붙여넣으면 대부분 해결됩니다.
