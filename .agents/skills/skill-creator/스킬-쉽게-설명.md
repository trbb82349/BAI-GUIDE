# skill-creator 쉽게 설명

## 이 스킬은 무엇을 해주나요?

새로운 "스킬"(AI가 특정 작업을 더 잘하게 도와주는 전문 설명서 겸 도구 모음)을 만들거나, 기존 스킬을 고칠 때 따라야 할 규칙과 절차를 알려주는 스킬입니다. 스킬을 만드는 방법을 알려주는 스킬이라, "메타 스킬"이라고 부릅니다.

## 언제 자동으로 켜지나요?

아래처럼 말하면 자동으로 켜집니다.

- "새 스킬 만들어줘"
- "이 스킬 좀 개선해줘 / 고쳐줘"
- "이런 작업을 자동으로 도와주는 스킬을 만들고 싶어"

## 이 스킬이 왜 필요한가요?

스킬은 AI에게 "이 종류의 작업은 이렇게 하는 거야"라고 미리 가르쳐두는 매뉴얼과 같습니다. 그런데 이 매뉴얼을 아무렇게나 길게 쓰면, AI가 참고할 때마다 너무 많은 내용을 읽어야 해서 느려지고 헷갈립니다. 이 스킬은 "꼭 필요한 내용만 짧게 담고, 자세한 내용은 필요할 때만 펼쳐보는 참고 문서로 분리하라"는 원칙, 그리고 "어떤 상황에 이 스킬을 자동으로 켤지"를 명확히 정의하는 방법을 알려줘서, 새로 만드는 스킬이 실제로 쓸모 있고 효율적으로 작동하게 도와줍니다.

## 이 스킬 안에 나오는 용어 쉽게 풀이

- **SKILL.md**: 스킬마다 반드시 있어야 하는 핵심 설명 파일. "이 스킬은 뭘 하는지"와 "언제 써야 하는지"가 맨 위에 적혀 있고, 그 아래 구체적인 사용법이 이어집니다.
- **프론트매터(Frontmatter)**: SKILL.md 맨 위에 있는 `name`, `description` 같은 짧은 요약 정보. AI는 평소엔 이 요약만 보고 있다가, 상황이 맞으면 그제서야 본문 전체를 읽습니다.
- **점진적 공개(Progressive Disclosure)**: 처음엔 아주 짧은 요약만 보여주고, 실제로 필요할 때만 자세한 내용을 펼쳐서 보여주는 방식. 책의 목차만 먼저 보고, 필요한 장만 펼쳐 읽는 것과 비슷합니다.
- **scripts/**: 스킬 안에 들어있는 실행 가능한 코드 파일들. 매번 같은 코드를 새로 짜지 않도록 미리 만들어둔 도구입니다.
- **references/**: 필요할 때만 불러와서 참고하는 상세 문서 폴더. 자주 안 쓰는 세부 내용을 여기로 빼서, 핵심 설명(SKILL.md)을 짧게 유지합니다.
- **assets/**: 완성된 결과물에 실제로 들어가는 재료 파일들(로고 이미지, 발표자료 템플릿, 폰트 파일 등). 설명 문서가 아니라 "그대로 갖다 쓰는 부품"입니다.
- **패키징(package_skill.py)**: 다 만든 스킬 폴더를 다른 사람과 공유할 수 있는 하나의 압축 파일(.skill)로 묶어주는 마지막 단계.

## 사용할 때 알아두면 좋은 점

- 새 스킬을 만들 때는 "이 스킬을 쓸 때 사용자가 실제로 어떤 말을 할지" 구체적인 예시부터 정하고 시작하는 게 좋습니다.
- README나 설치 가이드 같은 부가 문서는 스킬 폴더 안에 넣지 않습니다. 오직 AI가 작업하는 데 필요한 내용만 담습니다.
- 스킬 본문(SKILL.md)은 너무 길어지면(약 500줄 이상) 세부 내용을 별도 참고 파일로 분리해야 합니다.
- 실제로 스킬을 써본 뒤 아쉬운 점이 보이면, 그 경험을 바탕으로 스킬 내용을 계속 다듬어가는 게 정상적인 과정입니다.
