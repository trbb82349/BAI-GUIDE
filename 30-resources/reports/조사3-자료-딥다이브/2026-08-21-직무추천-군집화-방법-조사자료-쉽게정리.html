CareerLens B팀 · 조사 3 자료 정리 · 2026.08.21

비슷한 직무끼리
묶어서 추천하는 방법, 쉽게 이해하기

사용자가 관심 있는 업무를 여러 개 고르면 비슷한 직무를 묶어서 보여주는 기능을 만들려고 합니다. 이걸 실제로 논문·공식 분류체계·기술 기업이 어떻게 해왔는지 찾아본 자료 8개를, 처음 보는 사람도 이해할 수 있도록 정리했습니다.

이 문서에서 다루는 자료 공식 분류표 2개학술 논문 3개실무 사례 1개설명가능성 논문 2개

01 결론 먼저

  • 직무를 "묶어서" 추천하는 방법은 크게 두 갈래입니다. ① 사람이 미리 정해둔 분류표를 쓰는 방법과 ② 컴퓨터가 직무 설명 문장을 읽고 자동으로 비슷한 것끼리 묶는 방법입니다.
  • 실제로 잘 되는 서비스(LinkedIn)는 이 두 가지를 섞어서 씁니다 — 사람이 먼저 큰 틀을 잡고, 컴퓨터가 세부적으로 계산합니다.
  • 최근 연구들은 "컴퓨터가 왜 이 직무를 추천했는지"를 사람이 이해할 수 있는 문장으로 같이 보여주는 것도 중요하게 다룹니다.
  • CareerLens에는 ①번을 주된 방법으로 쓰고, ②번은 검증용으로 더하고, "왜 추천했는지" 설명 문장을 함께 보여주는 방향을 제안합니다. (자세한 내용은 06번 표)

02 그룹 A · 사람이 미리 정해둔 분류표

비유로 먼저 이해하기 — 도서관에서 책을 정리하는 방법을 떠올려보세요. 사서(전문가)가 미리 "문학", "과학", "역사" 같은 큰 서가를 만들어두고, 새 책이 들어오면 사람이 판단해서 어울리는 서가에 꽂습니다. 이 방법은 사람이 정한 기준이라 "왜 이 책이 여기 있는지" 설명하기 쉽지만, 새로운 종류의 책이 자주 나오면 사서가 계속 손봐야 합니다.

실제 자료

O*NET — 미국 정부가 운영하는 직업 정보 사이트

미국 노동부가 후원하는 O*NET은 모든 직업을 14개의 큰 묶음(커리어 클러스터)과, "실제로 하는 업무·필요한 기술·교육 수준"을 기준으로 나눈 더 세부적인 묶음(Job Family, 23개)으로 정리해둔 공식 자료입니다. "관심 업무 태그로 직무를 묶는 방식"이 바로 이 아이디어와 같습니다 — 사람이 미리 기준을 정해두고, 그 기준으로 직무를 분류하는 것입니다.

O*NET · Career Clusters 바로가기

ESCO — 유럽연합이 만든 직업·기술 분류표

유럽연합이 "직업"과 "그 직업에 필요한 기술"을 각각 목록으로 만들고, 서로 연결해둔 자료입니다. 예를 들어 "SQL"이라는 기술이 여러 직업에서 같이 등장한다면, 그 직업들은 자동으로 "비슷한 직업"으로 가까워집니다. 사람이 만든 표 위에서, 기술이 겹치는 정도로 유사도를 계산하는 방식입니다.

ESCoE · Linking skills to occupations

03 그룹 B · 컴퓨터가 문장을 읽고 자동으로 묶는 방법

비유로 먼저 이해하기 — 여러 학생이 쓴 자기소개서 100장을 사람이 하나하나 읽지 않고, 컴퓨터에게 맡긴다고 생각해보세요. 컴퓨터는 "데이터", "고객", "분석" 같은 단어가 자기소개서마다 몇 번 나오는지 세어서 숫자로 바꾸고, 비슷한 단어를 비슷한 횟수로 쓴 자기소개서끼리 자동으로 그룹을 만듭니다. 사람이 기준을 정하지 않아도 되지만, "왜 이렇게 묶였는지"는 계산 결과를 봐야만 알 수 있습니다.

먼저 알아두면 좋은 단어 3개

벡터(vector)
문장을 컴퓨터가 계산할 수 있는 "숫자 목록"으로 바꾼 것. 예: "이 직무 설명에 데이터라는 단어가 3번, SQL이 2번 나온다" → [3, 2, 0, 1, ...] 같은 숫자 나열.
유사도(similarity)
두 숫자 목록이 얼마나 비슷한지 재는 잣대. 흔히 "코사인 유사도"나 "거리(distance)"라는 계산법을 씁니다 — 숫자가 비슷할수록 두 직무가 비슷하다고 봅니다.
군집화(클러스터링, clustering)
유사도가 높은 것들을 자동으로 같은 그룹으로 묶는 작업. "K-Means"는 그중 가장 널리 쓰이는 계산 방법 이름입니다.

실제 자료

직무특성 기반 직업추천 프로그램 개발에 관한 연구 (국내 논문)

재직자(이미 그 일을 하는 사람)와 구직자의 데이터를 각각 숫자 목록으로 만든 뒤, 두 목록이 얼마나 가까운지(유클리디안 거리)를 계산해서 직업을 추천하는 국내 연구입니다. "거리가 가까우면 비슷한 직무"라는 발상을 실제 논문으로 확인할 수 있습니다.

KCI · 논문 원문 바로가기

Job Recommendation based on Job Profile Clustering

수많은 채용공고의 텍스트를 컴퓨터가 읽고, 공통된 특징을 기준으로 자동으로 그룹(클러스터)을 나눈 다음, 구직자를 그 그룹에 매칭하는 연구입니다. CareerLens로 치면 "여러 직무를 사람이 하나씩 분류하지 않고, 설명 텍스트만으로 자동으로 비슷한 것끼리 묶는" 것과 같은 방식입니다.

ScienceDirect · 논문 PDF

Improving Clustering on Occupational Text Data through Dimensionality Reduction

직무 설명 텍스트를 벡터로 바꾼 다음, 계산을 더 쉽게 하려고 숫자 목록의 길이를 줄이는 작업(차원 축소)을 거쳐 그룹으로 묶는 최신 실험 논문입니다. "텍스트 → 숫자 → 그룹" 과정을 가장 최근 방식으로 보여주는 자료입니다.

arXiv · 논문 원문

04 그룹 C · 실제 회사는 이렇게 씁니다

LinkedIn Skills Graph

LinkedIn은 전 세계 사용자가 프로필에 적어둔 3,900만 개의 기술(스킬) 이름을 갖고 있습니다. 이 기술들이 어떤 직무들에서 같이 자주 등장하는지를 계산해서, "이 직무에는 이런 기술 묶음이 핵심적이다"라는 그룹을 자동으로 만듭니다.

이 사례가 중요한 이유는, 그룹 A(사람이 정한 기준)와 그룹 B(컴퓨터 자동 계산)를 섞은 하이브리드이기 때문입니다 — 사람이 먼저 기술 이름을 정리해두고(A방식), 그다음 어떤 기술들이 같이 나타나는지는 컴퓨터가 계산합니다(B방식). 우리가 06번 표에서 제안하는 방향과 같은 구조입니다.

LinkedIn Engineering Blog

05 그룹 D · "왜 이 직무를 추천했나요?"를 설명해주는 방법

비유로 먼저 이해하기 — 쇼핑몰 앱이 "이 상품 어때요?"라고만 추천하면 신뢰가 잘 안 가지만, "당신이 최근에 산 물건과 같이 자주 팔린 상품이에요"라고 이유를 알려주면 훨씬 납득이 됩니다. 직무 추천도 마찬가지입니다. 점수만 보여주는 대신 "왜 이 직무를 추천했는지" 근거 문장을 같이 보여주는 연구들이 있습니다.

Toward a traceable, explainable, and fair JD/Resume recommendation system

추천 결과에 숫자 점수만 보여주지 않고, "이력서의 어떤 단어와 채용공고의 어떤 조건이 매칭됐는지"를 근거로 함께 보여주는 설명 구조를 제안한 논문입니다.

arXiv · 논문 원문

Developing an Intelligent Job Recommendation System Using Semantic Retrieval and Explainable AI

매칭된 단어, 적용된 조건, 근거 자료를 함께 정리해서 보여주는 "설명 계층"을 시스템에 넣은 사례입니다.

06 CareerLens 프로젝트에는 뭘 쓰면 좋을까

방법핵심 아이디어CareerLens에 적용하는 방법
그룹 A
규칙 기반		사람이 미리 정한 기준(관심 업무 태그·분류표)으로 직무를 묶음관심 업무 태그가 얼마나 겹치는지 계산해서 직무 묶음을 만드는 주된 방법으로 사용
그룹 B
콘텐츠 기반		직무 설명 텍스트를 컴퓨터가 읽고 자동으로 유사도를 계산태그 기반 결과와 얼마나 일치하는지 대조하는 검증용으로만 사용
그룹 D
설명 가능성		추천 이유를 근거 문장으로 함께 보여줌직무 묶음마다 "어떤 태그가 겹쳐서 같이 묶였는지" 설명 문장을 함께 제공

07 아직 확인 안 된 것

  • 01그룹 A(태그 겹침)와 그룹 B(텍스트 유사도) 결과가 서로 다르게 나오는 직무 쌍이 있는지 실제 직무 데이터로 직접 계산해봐야 확인 가능
  • 02텍스트 유사도 계산을 어떤 도구로 할지 엑셀 수식 수준으로 충분한지, 파이썬 코드가 필요한지 팀 역량에 맞춰 결정
  • 03직무 묶음 이름(클러스터 이름)을 사람이 붙일지, 자동으로 정할지 사용자에게 보여줄 때 이해하기 쉬운 이름이 필요
