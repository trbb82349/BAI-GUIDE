직무지도 데모 — 알리오 공고 기반

공공기관 채용공고(job.alio.go.kr)에서 실제 업무·필요지식·필요기술 텍스트를 뽑아, 직무 카테고리 간 키워드 유사도로 지도를 그렸습니다.
원(노드) 크기 = 확보된 채용공고 역할 수, 선 굵기 = 두 직무가 공유하는 업무·역량 키워드의 유사도. 노드를 클릭하면 실제 채용공고 근거가 오른쪽에 나옵니다.

CRM분석은 점선 원으로 표시했습니다 — 이번 수집 범위(알리오)에서는 실제 CRM 업무 공고를 찾지 못했습니다.

직무를 클릭해 보세요

지도의 원을 클릭하면 그 직무에 연결된 실제 채용공고와 핵심 키워드를 볼 수 있습니다.

지금까지 수집한 채용공고를 카드 제작 키트와 같은 방식(한 줄 설명 → 하는 일 → 필요 역량 → 회사소개 → 접수 정보)으로 정리했습니다. 왼쪽에서 직무명을 클릭하면 오른쪽에 카드가 뜹니다.

기존 취업사이트는 직무를 각각 따로 보여주지만, 실제 회사의 채용공고를 보면 서로 다른 직무에서도 비슷한 업무나 역량이 많이 나타납니다.

직무지도는 이런 공통점을 실제 채용공고에서 찾아서, 어떤 직무들이 서로 연결되어 있는지를 한눈에 보여주는 서비스입니다.

예를 들어 '데이터 분석'과 '마케팅 분석'이 별개의 직무처럼 보이더라도, 실제 공고를 분석해보면 고객 데이터 분석, KPI 분석 등의 업무가 겹칠 수 있습니다. 직무지도에서는 이런 관계를 선으로 연결해서 보여줍니다.

즉, 직무를 단순히 분류해서 보여주는 것이 아니라, 실제 채용공고를 통해 직무와 직무 사이의 관계를 보여주는 것이 핵심입니다.

"직무 목록"이 아니라 "직무 관계망"

취업 사이트에서 "데이터 분석"을 검색하면 보통 카테고리 하나에 걸린 공고 목록이 나옵니다. 그런데 실제 채용공고를 들여다보면, 데이터 분석·BI·마케팅 분석·CRM 분석은 이름은 달라도 겹치는 업무와 요구 역량이 상당히 많습니다. 반대로 같은 "경영·회계·사무"로 분류돼도 실제 업무는 완전히 다른 경우도 흔합니다.

직무지도는 이 지점에서 출발합니다. 미리 정해둔 분류 체계에 공고를 끼워 맞추는 대신, 실제 공고에 적힌 업무·필요지식·필요기술 텍스트가 서로 얼마나 겹치는지를 계산해서 직무 사이의 거리를 정합니다.

기존 채용사이트의 분류직무지도
기준사람이 미리 정한 카테고리공고에 실제로 적힌 업무·역량 텍스트
답하는 질문"이 공고는 어디에 속하는가""이 직무는 무엇과 연결되어 있는가"
공고 하나가보통 카테고리 하나에만 속함여러 직무 영역에 동시에 걸릴 수 있음

왜 "지도"라는 형태가 중요한가

지도는 "데이터 분석과 마케팅은 얼마나 가까운가", "데이터 분석을 하던 사람이 CRM으로 이동할 수 있는가", "내가 가진 역량을 살릴 수 있는 다른 직무는 무엇인가" 같은 질문에 답할 수 있습니다. 지금 데모의 지도에서 데이터분석과 AI·ML이 가장 굵은 선으로 이어진 것도, 두 직무가 실제로 Python·데이터 분석·통계 같은 키워드를 많이 공유하고 있기 때문입니다 — 사람이 임의로 정한 게 아니라 텍스트 유사도 계산 결과입니다.

이 지도에서 CRM분석이 점선(데이터 없음)으로 남아있는 것도 같은 원리입니다. 실제로 그 직무를 뒷받침하는 공고를 못 찾았기 때문에, 억지로 채우지 않고 비어있는 채로 정직하게 보여줍니다.

다중 소속 문제가 자연스럽게 풀림

"고객 행동 데이터를 분석해서 마케팅 전략을 세우는 직무는 데이터분석일까, 마케팅일까?" 같은 질문은 기존 분류 체계에서는 골치 아픈 문제입니다. 직무지도에서는 오히려 당연합니다 — 하나의 공고가 여러 직무 노드와 동시에 연결될 수 있다는 전제로 설계되어 있기 때문입니다. 지금 데모에서도 일부 역할(예: IBK기업은행의 데이터 기반 마케팅 직무)은 마케팅분석 노드에 속해 있지만, 그 안의 텍스트("데이터 분석 도구 활용", "A/B 테스트 설계")가 데이터분석·AI·ML 노드와의 연결선을 함께 끌어올리고 있습니다.

온톨로지가 하는 역할

여기서 온톨로지는 단순히 "이 공고는 이 카테고리"라고 태그를 붙이는 분류 기술이 아니라, 회사 → 공고 → 업무 → 역량 → 직무 → 관련 직무로 이어지는 관계망을 표현하는 도구로 씁니다. 지금 데모는 이 관계망의 가장 단순한 형태(카테고리 5개 사이의 유사도)만 구현했지만, 같은 방식을 역할(공고) 단위로 확장하면 "이 공고와 저 공고가 왜 가까운지"까지 보여줄 수 있습니다.

카드 제작 키트와의 연결

직무지도에서 노드를 클릭했을 때 나오는 "하는 일 / 필요지식 / 필요기술"은 30-resources/카드 제작 키트가 채용공고 한 장을 이해하기 쉬운 카드로 바꿀 때 쓰는 것과 같은 종류의 정보입니다. 지금은 텍스트 목록으로만 보여주지만, 같은 데이터를 카드 키트의 디자인에 흘려보내면 "지도에서 직무를 탐색하다가, 관심 가는 공고는 카드로 바로 확인한다"는 흐름을 만들 수 있습니다.

이 프로젝트가 답하려는 핵심 질문

"채용공고에서 추출한 업무와 요구 역량을 바탕으로, 직무 간 연결성을 어떤 기준으로 정의하고 시각화할 것인가?"

지금 쓰고 있는 기준은 TF-IDF 키워드 유사도이지만, 업무 유사도·역량 유사도·산업 유사도·공고 키워드 유사도 중 무엇을 쓰느냐에 따라 지도의 모양이 달라질 수 있습니다. 이 기준을 어떻게 정하고 검증할지가 이 프로젝트의 기술적 핵심입니다. (자세한 계산 방식은 "어떻게 만들었나" 탭을 참고하세요.)

데이터가 만들어진 과정

이 지도는 사람이 그린 다이어그램이 아니라, 실제 공공기관 채용공고(job.alio.go.kr, 잡알리오)에서 뽑은 텍스트를 계산해서 만들었습니다. 아래 4단계 스크립트가 순서대로 돌아갑니다.

  1. 공고 수집 — scrape_postings.py
    직무 카테고리별 키워드(예: 데이터분석/빅데이터/데이터사이언티스트)로 알리오를 검색합니다. 처음엔 검색 결과 아무데나 키워드가 있으면 다 가져왔더니, "고객관리"로 검색해서 실제로는 상수도 현장직 채용공고가 잡히는 오탐이 많았습니다. 그래서 제목에 키워드가 실제로 들어있는 공고만 채택하도록 바꿨습니다.
  2. 업무 텍스트 추출 — extract_job_descriptions.py
    공고 상세 페이지에는 응시자격·전형절차 같은 행정 정보만 있고, 실제 "하는 일"은 첨부된 직무기술서 PDF에만 있었습니다. PDF 양식이 기관마다 달라서, NCS 표준 형식을 쓰는 것만 정규식으로 자동 인식하고, 나머지는 사람이 직접 읽어서 정리했습니다.
  3. 역할 데이터 정리 — combine_roles.py
    자동 추출분과 수동 정리분을 합치고, 같은 PDF 안에 섞여 있던 무관한 역할(예: AI 채용 PDF 안의 발전소 안전관리원)을 제외해서 최종 15개 역할로 정리했습니다.
  4. 유사도 계산 — build_similarity.py
    카테고리별로 소속 역할들의 "하는 일 + 필요지식 + 필요기술" 텍스트를 합친 뒤, TF-IDF로 키워드 가중치를 매기고 코사인 유사도로 카테고리 간 거리를 계산했습니다. "의사소통능력"처럼 모든 공고에 상투적으로 들어가는 표현은 미리 제거했습니다.

왜 TF-IDF인가

단순히 키워드가 몇 번 나왔는지(빈도)만 세면, "책임감"·"엑셀 활용" 같은 범용 표현이 모든 직무 쌍을 "비슷하다"고 만들어 버립니다. TF-IDF는 "이 직무군에는 자주 나오지만 전체적으로는 드문 키워드"에 가중치를 더 줘서, SQL·Tableau·마케팅 같은 실제 직무를 구분 짓는 단어가 유사도 계산을 주도하게 합니다.

지도를 읽는 법 (인코딩 기준)

원 크기 = 그 직무에서 확보된 채용공고 역할 수. 클수록 데이터가 많다는 뜻입니다.
점선 원 = 이번 수집 범위에서 데이터를 찾지 못한 직무(CRM분석).
굵고 진한 선 = 두 직무의 코사인 유사도가 높음 (업무·역량 키워드를 많이 공유).
가늘고 옅은 선 = 유사도가 낮음. 유사도 2% 미만인 쌍은 아예 선을 그리지 않았습니다.

한계 (다음에 보강할 부분)

  • 직무당 역할 수가 1~8개로 적어서, 유사도 수치가 통계적으로 안정적이라기보다는 "지금 확보한 표본 안에서의 경향"에 가깝습니다.
  • 한국어 형태소 분석기 없이 정규식으로 토큰을 뽑아서, 조사가 안 떨어져 나가는 등 키워드 추출이 완벽하지 않습니다.
  • CRM분석은 공공기관 채용공고 안에서 데이터를 거의 찾지 못했습니다. "CRM"이라는 표현 자체가 이 데이터 소스에 잘 안 쓰이는 것으로 보입니다.
  • 지금은 카테고리(5개) 단위로만 유사도를 계산합니다. 역할(15개) 단위로 계산하면 "이 공고와 저 공고가 왜 가까운지"까지 더 세밀하게 보여줄 수 있습니다.
