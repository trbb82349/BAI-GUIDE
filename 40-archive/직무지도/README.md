# 직무지도 데모

## 한 줄 목표

공공기관 채용공고(알리오)를 직무 키워드로 수집 → 직무기술서 PDF에서 실제 업무·역량 텍스트 추출 → 직무 카테고리 간 키워드 유사도 계산 → 지도(노드-엣지 그래프)로 시각화.

## 작업 카드

목표: "직무 목록"이 아니라 "실제 공고에서 나타나는 업무·역량이 얼마나 겹치는가"로 직무 간 연결을 보여주는 지도 만들기
입력: `job.alio.go.kr`의 공개 채용공고 (제목에 직무 키워드가 포함된 공고만 채택)
출력: `output/job_map.html` — 5개 직무(데이터분석/BI/CRM분석/마케팅분석/AI·ML) 노드와 유사도 기반 연결선을 보여주는 지도(탭1), 15개 역할을 카드 제작 키트 스타일로 정리한 공고 카드 목록(탭2), 프로젝트 취지 설명(탭3), 제작 과정 설명(탭4)
성공 기준: `output/job_map.html`을 Chrome으로 열었을 때 노드 5개, 연결선이 보이고, 노드를 클릭하면 오른쪽에 실제 공고의 하는 일/필요지식/필요기술이 뜨는 것
오늘 만든 최소 버전: 5개 카테고리, 실제 역할 15개 (CRM분석은 데이터를 찾지 못해 "데이터 없음" 노드로 표시)

## 파이프라인 (실행 순서)

```bash
python src/scrape_postings.py          # 1. 알리오에서 직무 키워드로 공고 목록+상세 수집 -> output/postings.json
python src/extract_job_descriptions.py # 2. 첨부된 직무기술서 PDF를 받아 역할별 텍스트 자동 추출 -> output/job_roles.json
                                        #    (형식이 다른 PDF는 output/unmatched_pdfs.json에 남고, 사람이 직접 읽어서
                                        #     input/manual_roles.json에 수동으로 추가함)
python src/combine_roles.py            # 3. 자동+수동 역할을 합치고 무관한 역할을 걸러 -> output/job_roles_final.json
python src/build_similarity.py         # 4. 카테고리별 TF-IDF 유사도 계산 -> output/job_map_data.json
```

`output/job_map.html`은 `job_map_data.json`을 파일 안에 그대로 내장하고 있어서 재실행 없이 브라우저로 바로 열어볼 수 있습니다. 데이터를 바꾸면 4번 스크립트를 다시 돌린 뒤, `output/job_map_data.json`의 내용을 `job_map.html`의 `const JOB_MAP_DATA = ...` 부분에 다시 넣어야 합니다 (지금은 수동 삽입 — 자동화하려면 요청해주세요).

## 만든 기능

- 직무 키워드(제목에 실제로 포함된 것만)로 알리오 공고 수집, 상세 페이지의 표(응시자격·NCS분류 등) 파싱
- 첨부된 "직무기술서" PDF에서 역할별 하는 일/필요지식/필요기술 자동 추출 (NCS 표준 형식 PDF만 자동 인식, 나머지는 수동 검토)
- 카테고리별 텍스트를 TF-IDF로 벡터화해 코사인 유사도 계산 (범용 역량 단어는 STOPWORDS로 제거)
- SVG 기반 지도: 노드 크기 = 역할 수, 선 굵기·진하기 = 유사도, 클릭 시 실제 공고 근거 패널 표시

## 확인 방법

`output/job_map.html`을 Chrome으로 엽니다. 노드 5개가 보이고, 클릭하면 오른쪽에 그 직무의 실제 채용공고(기관명, 역할명, 하는 일, 필요지식, 필요기술)가 나오는지 확인합니다.

## 알게 된 것 (다음에 참고)

- **알리오 상세 페이지 HTML에는 실제 업무 설명이 없습니다.** 응시자격·전형절차 같은 행정 정보만 있고, "무슨 일을 하는지"는 첨부된 PDF(직무기술서)에만 있습니다.
- **직무기술서 PDF 양식이 기관마다 완전히 다릅니다.** NCS 표준 형식("【NCS기반 채용 직무 설명자료 : 역할명】")을 쓰는 기관도 있지만, 완전히 다른 자체 양식을 쓰는 기관이 더 많아서 정규식 자동 파싱은 일부만 성공합니다 (이번엔 자동 7개 + 수동 8개로 15개 확보).
- **알리오 검색은 제목이 아니라 본문 아무데나 키워드가 있어도 걸립니다.** "고객관리"로 검색했더니 실제로는 상수도 현장직 이름이었던 사례가 있어서, 제목에 키워드가 실제로 있는 공고만 채택하도록 필터를 넣었습니다 (`src/scrape_postings.py`의 `title_matches`).
- **CRM분석은 알리오(공공기관 채용) 안에서 데이터를 거의 못 찾았습니다.** "CRM"이라는 표현 자체가 공공기관 채용공고 제목에 잘 안 쓰이는 것으로 보입니다. 민간 채용 사이트나 다른 검색어로 넓히면 채워질 수 있는 자리입니다.

## Codex에게 다음에 요청할 말

> "직무지도 데이터를 더 넓혀줘 — CRM분석 카테고리를 채울 다른 검색어나 데이터 소스를 찾아보고, 데이터분석/BI도 몇 개 더 모아줘."

또는

> "카드 제작 키트 스타일로, 지도에서 직무를 클릭했을 때 지금처럼 텍스트 목록이 아니라 예쁜 카드 형태로 보여줘."

## 메모

- 알리오는 robots.txt에 별도 제한이 없고, `/mobile2021/` 경로는 서버 렌더링 HTML이라 가벼운 스크래핑(requests+BeautifulSoup)으로 충분합니다.
- 요청 사이 0.5초 대기(`REQUEST_DELAY`)를 넣어서 공공 사이트에 부담을 최소화했습니다.
- `input/job_description_pdfs/`에 내려받은 원본 PDF가 남아있습니다 (재실행 시 이미 있으면 다시 안 받음).
