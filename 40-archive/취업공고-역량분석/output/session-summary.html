취업공고 역량분석 — 진행 요약

데이터과학과 1학년 · AI agent 동아리 포트폴리오 방향 탐색 세션 (2026-08-01)

목표

취업공고 사이트에서 실제 채용공고를 모아 기업이 요구하는 역량을 파악하고, 이를 바탕으로 포트폴리오 방향을 잡는 것. 동아리 이번 주 숙제 — "채용공고 수집 프로그램을 만든 뒤, 나에게 맞는 분야를 찾고 앞으로 할 프로젝트의 방향성을 잡는다."

진행 과정

채용공고 수집 대상 결정

사람인·잡코리아를 놓고 robots.txt를 실제로 확인. 사람인은 채용 상세 페이지가 명시적으로 차단돼 있어 보류하고, 잡코리아의 /recruit/ai-jobs(AI잡스, ClaudeBot에도 허용된 경로)로 시작.

robots.txt 확인법적/윤리 리스크 점검

스크래퍼 제작 (Playwright)

정적 HTML만으로는 공고 카드가 안 보여 Playwright로 전환. 카드 DOM 구조를 분석해 회사명·제목·기술태그·경력·지역·마감일을 추출하는 스크립트 제작. 50건 → 100건으로 확대 (이 페이지는 100건 근처가 스크롤 상한).

scrape_jobkorea_ai_jobs.py

"코딩 역량보다 업종을 먼저 보고 싶다" → 업종 분류

회사소개 텍스트를 추가로 수집하고, 키워드 기반 규칙으로 10개 업종 카테고리에 공고를 분류. 결과: 모빌리티/로보틱스 34%, 제조 23%, 헬스케어 13%, IT서비스 12%, 나머지 소수. 분류 과정에서 "강화학습"이 "교육"으로 잘못 묶이는 버그를 발견해 수정.

classify_domain.py

업종별 기술 스택 분석

Python은 거의 모든 업종에서 1위(공통 스킬), 업종을 가르는 건 2~3순위 스킬 (모빌리티=C++/ROS, 제조=Oracle/C#/JAVA, 헬스케어=SQL/NoSQL/RDBMS).

analyze_skills_by_domain.py

한눈에 보기 HTML 대시보드

수집 현황·업종 분포·기술 TOP15·업종별 상세를 정적 HTML 한 파일로 정리. CSV를 다시 읽어서 그리는 방식이라 데이터가 늘어나면 재실행만으로 갱신됨.

관심 업종 좁히기 (IT서비스 · 금융 · 헬스케어)

"1학년, 코딩 경험 0" 상태에서는 스킬 갭이 모든 업종에서 100%라 스킬 기준 비교가 의미 없다는 점을 짚고, 대신 "업종에서 어떤 종류의 일을 하는가" 관점으로 브레인스토밍. 세 업종에 관심이 있다는 답을 받음.

"현재 공고 수"와 "미래 성장 전망"은 다른 질문

정부 통계·산업 리포트 기반 성장 전망 리서치를 백그라운드 에이전트로 실행. 1차 실행이 완료로 보고했지만 실제 파일이 없어 재실행으로 바로잡음. 이후 보완 조사가 한 번 더 붙으며 헬스케어 평가가 "중(불확실)" → "중~강"으로 상향(AI 채용공고 123%↑, 원격의료 법제화 확인).

포트폴리오 프로젝트 방향 브레인스토밍

"바이브코딩만 해봤고 실제 코딩 지식은 없음" + 교수님의 "제품 → 실사용자 데이터 분석" 제안을 함께 검토. 낯선 유저를 모으는 대신, 이번 주 분석 결과 자체를 에이전트로 감싸서 동아리 친구들이 실제로 궁금해할 질문에 답하는 방향으로 결정.

Q&A 에이전트 v1 제작

LLM API 키가 없어 키워드 매칭 기반으로 우선 구현. 업종 이름과 의도 키워드(스킬/전망/현황)를 인식해 이미 만든 데이터로 답하고, 모든 질문·답변을 로그로 남김 — 나중에 이 로그 자체가 "실사용자가 뭘 궁금해하는지" 보여주는 데이터가 됨. 테스트 중 Windows 콘솔 인코딩(cp949) 버그도 발견해 수정.

ask_agent.pynotes/agent_qa_log.csv

핵심 인사이트

  • 지금 공고가 많은 곳 ≠ 앞으로 늘어날 곳. 공고 수 스냅샷은 헬스케어(13%) > IT서비스(12%) > 금융(2%) 순이었지만, 성장 전망 리서치에서는 IT서비스가 가장 근거가 탄탄하고 헬스케어가 최근 가장 구체적인 성장 신호(채용공고 123%↑)를 보임.
  • Python은 업종을 안 가리는 공통 스킬이고, 업종의 정체성은 2~3순위 스킬에서 드러남(모빌리티=C++/ROS, 제조=Oracle/JAVA, 헬스케어=SQL/NoSQL).
  • 코딩 경험이 없을수록 "낯선 유저 확보"보다 "이미 아는 사람 대상 반복 사용 도구"가 현실적. 이번 주 분석 결과를 에이전트로 감싸는 게 가장 빠르게 "실사용자 데이터"를 쌓을 수 있는 경로였음.
