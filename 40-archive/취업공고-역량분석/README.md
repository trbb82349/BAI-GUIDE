# 취업공고 역량분석

취업공고 사이트에서 실제 채용공고를 모아, 기업이 요구하는 역량(기술 스택 등)을 파악하고
이를 바탕으로 포트폴리오 방향을 잡기 위한 프로젝트.

진행 순서: 1단계 공고 수집 → 2단계 업종/분야 군집화(완료) → 3단계 군집별 역량 분석(예정)

## 지금 상태 (2026-08-01)

- **잡코리아 AI잡스** (`https://www.jobkorea.co.kr/recruit/ai-jobs`, 데이터/AI 직무 전용 페이지)에서
  100건 수집 완료 → `output/jobkorea_ai_jobs_20260801_1845.csv`
- 위 100건에 업종/분야 라벨을 붙인 결과 → `output/jobkorea_ai_jobs_20260801_1845_domain.csv`
- **사람인**은 아직 시작 안 함 (아래 "사람인 진행 보류 사유" 참고)

|---|---|---|

**인사이트**: "AI/데이터" 직무 공고라고 해서 IT서비스 기업에 가장 많이 몰려있는 게 아니라,
실제로는 로봇/자율주행/제조자동화 쪽(모빌리티+제조 합쳐서 57%)에 데이터·AI 인력 수요가
훨씬 많았음. 표본이 잡코리아 "AI잡스" 큐레이션 페이지 100건이라 실제 시장 전체 비율과는
차이가 있을 수 있음(사람이 아니라 큐레이션 알고리즘이 고른 공고들).

## 관심 업종 성장 전망 (리서치, 공고 스냅샷과는 다른 질문)

위 업종 분포는 "지금 이 순간 공고가 얼마나 있나"고, 아래는 "앞으로 수요가 늘어날 곳은 어디인가"를
정부 통계·산업 리포트로 따로 조사한 결과(전체 근거·출처·한계: `notes/domain-demand-outlook-2026.md`).

| 업종 | 성장 전망 | 근거 요약 |
|---|---|---|
| IT서비스/플랫폼 | 강 | 국가통계 3종(SW·AI·데이터산업 실태조사) 일치 + 클라우드산업 실제 25%대 성장(2024). 다만 AI 채용공고 증가율 자체는 top5 밖(이미 규모가 커서 증가율은 완만) |
| 금융/핀테크 | 중~강 | 정책 드라이버(마이데이터 2.0, 생성형AI 지원방안)는 가장 뚜렷하나, AI 채용공고 증가율 top5에도 못 들 만큼 업종 전체 성장 신호는 셋 중 가장 약함 |
| 헬스케어/의료AI | 중~강 | AI 채용공고 123%↑(조사 대상 10개 산업 중 4위) + 원격의료 법제화(2026.12 시행)로 최대 걸림돌이던 규제가 완화되는 중. 다만 국가통계 수준의 인력 부족률 수치는 여전히 미확보 |

"강/중/약"은 업종의 절대적 성장 속도가 아니라 이번 조사에서 확보한 근거의 양과 일관성 기준
상대 평가임에 유의 (예: 금융은 표본이 애초에 잡코리아 100건 중 2건뿐이라 국내 공개 통계 자체가 적음).

**리서치가 두 차례 진행됐음**: 처음엔 헬스케어를 "중, 불확실성 큼"으로 봤는데, 보완 조사에서
"AI 채용공고 123%↑(4위)"와 "원격의료 법제화(2026.12 시행)"가 추가로 확인되며 금융과 동급인
"중~강"으로 올라감. 반대로 금융은 "AI 채용공고 증가율 top5에도 못 든다"는 사실이 추가되며
셋 중 성장 신호가 가장 약한 쪽으로 재평가됨. 전체 근거는 `notes/domain-demand-outlook-2026.md` 참고.

## 왜 잡코리아부터, 왜 이 페이지인가

- 사람인은 `robots.txt`에서 채용 상세 페이지(`/zf_user/recruit/view/`, `recruit_view.php`)를
  명시적으로 `Disallow` 처리하고 있어 우선 보류함. 두 사이트 모두 이용약관상 자동 수집을
  금지하는 조항이 있는 것으로 알려져 있어, robots.txt로 명시적으로 열려 있는 범위 안에서만 진행.
- 잡코리아 `robots.txt`는 ClaudeBot 등 AI 크롤러에도 `/recruit/joblist`, `/Recruit/GI_Read`,
  `/recruit/ai-jobs`를 명시적으로 `Allow` 처리함. 반대로 검색 기능(`/Search/?stext=`,
  `/recruit/ai-jobs/search`)은 모든 크롤러에 차단되어 있어 **키워드 검색창 대신
  `/recruit/ai-jobs` 카테고리 페이지를 그대로 사용**함 (이 페이지가 데이터/AI 계열
  8개 직무를 기본으로 다 보여줘서 별도 검색 없이도 목적에 맞음).
- 이 페이지는 무한 스크롤이지만 실제로는 약 100건 근처에서 새 공고가 더 안 늘어남(스크롤을
  더 해도 정체됨). 그 이상 모으려면 다른 진입점(직무 카테고리별 페이지 등)을 추가로 찾아야 함.

## 1) 수집 스크립트 사용법

```powershell
# 프로젝트 폴더에서 실행
python src\scrape_jobkorea_ai_jobs.py --count 100
```

- `--count`: 수집할 공고 개수 (기본 50). 이 페이지는 실질적으로 100건 근처가 상한.
- `--output`: 저장 경로 직접 지정 (기본은 `output/jobkorea_ai_jobs_<날짜시간>.csv`)
- 실행 전 `robots.txt`를 매번 다시 확인하고, 허용되지 않으면 자동으로 중단함
- 스크롤 사이 1.5초씩 대기, 5번 연속 새 공고가 없으면 자동 종료 (서버 부담 최소화)

### 의존성

이번 세션에서 `playwright`, `pandas`를 설치하고 `playwright install chromium`까지 완료함
(다른 PC/환경이면 다시 설치 필요):

```powershell
python -m pip install playwright pandas beautifulsoup4 requests
```

## 2) 업종/분야 분류 스크립트 사용법

```powershell
python src\classify_domain.py
```

- 입력을 안 주면 `output/` 폴더에서 가장 최근 `jobkorea_ai_jobs_*.csv`를 자동으로 찾음
- `--input`, `--output`으로 경로 직접 지정 가능
- **방식**: 미리 정한 업종 카테고리(`classify_domain.py`의 `DOMAIN_RULES`)에 키워드로 배정하는
  규칙 기반 분류. 공고 제목 + 회사명 + 회사소개 텍스트를 합쳐서 키워드를 검색하고,
  가장 먼저 매칭되는 업종으로 확정함(리스트 위쪽일수록 우선순위 높음). 아무 키워드에도
  안 걸리면 `기타`로 분류.
- 결과 CSV에 `domain`(확정된 업종), `matched_keyword`(어떤 키워드로 걸렸는지) 컬럼이 추가됨.
  `matched_keyword`를 보면 왜 이 업종으로 분류됐는지 바로 확인 가능(투명성 확보 목적).
- **알려진 한계**: 키워드 매칭이라 애매한 경우가 있음. 예를 들어 "강화학습/머신러닝"이
  한때 "학습"이라는 단어 때문에 "교육" 업종으로 잘못 묶인 적이 있어서 `DOMAIN_RULES`에서
  `학습`/`러닝` 키워드는 뺐음. 분류가 이상해 보이면 `DOMAIN_RULES`에 키워드를 추가/조정하면 됨.

## 3) 군집별 역량 분석 스크립트 사용법

```powershell
python src\analyze_skills_by_domain.py
```

- 입력을 안 주면 `output/` 폴더에서 가장 최근 `*_domain.csv`를 자동으로 찾음
- `--top`으로 업종별 출력 개수 조정 (기본 10)
- 출력: 콘솔에 업종별 TOP 기술 요약 + `output/<입력파일명>_skills_by_domain.csv` (long format:
  domain, domain_posting_count, skill, skill_count, skill_pct_in_domain)

### 결과 요약 (100건, 상위 5개 업종만 — 나머지는 표본이 5건 이하라 참고용)

| 업종 (공고 수) | 1위 | 2위 | 3위 | 특징 |
|---|---|---|---|---|
| 모빌리티/로보틱스 (34) | Python 61.8% | C++ 52.9% | Pytorch 26.5% | ROS·CAD·CAN 등 하드웨어 통합 지식이 다른 업종엔 없음 |
| 제조/스마트팩토리 (23) | Python 30.4% | C/C++ 26.1% | Oracle·C#·Pytorch 17.4% | Oracle/JAVA/MSSQL 등 산업용 SW·DB 계열이 상대적으로 강함 |
| 헬스케어/제약/바이오 (13) | Python 53.8% | AWS·NoSQL·RDBMS·SQL 23.1% | Pytorch·Figma·MongoDB 15.4% | DB/데이터 인프라 비중이 다른 업종보다 높음 |
| IT서비스/플랫폼 (12) | Python 41.7% | Pytorch·Tensorflow 16.7% | - | fallback 성격 업종이라 도구가 제일 이질적(디자인·클라우드·보안 섞임) |
| 게임/교육/기타/미디어/금융 (합쳐서 18) | - | - | - | 업종당 2~5건뿐이라 통계적으로 의미 없음, 표본을 늘려야 신뢰 가능 |

**해석**: Python은 거의 모든 업종에서 1위라 "업종 안 가리는 공통 스킬"이고, 업종을 가르는 건
2~3순위 스킬임. 예를 들어 모빌리티는 C++이 유독 강하고(임베디드/제어), 제조는 Oracle/C#/JAVA 같은
전통 산업 IT 스택이 섞여 있고, 헬스케어는 SQL/NoSQL/RDBMS 등 데이터베이스 계열이 두드러짐.

## 4) 한눈에 보기 대시보드 (HTML)

```powershell
python src\build_dashboard.py
```

- 출력: `output/dashboard.html` — 더블클릭해서 브라우저로 열면 됨 (인터넷 연결 불필요, 파일 하나로 끝)
- 내용: 수집 현황 요약 → 업종/분야 분포(막대그래프) → 전체 공통 기술 TOP 15 →
  업종별 기술 스택 TOP 10(클릭해서 펼치기) → 진행 상태 체크리스트(완료 항목 ✅ / 예정 항목 ▢)
- `output/` 폴더의 최신 `*_domain.csv`, `*_skills_by_domain.csv`를 읽어서 매번 새로 그리기 때문에,
  나중에 데이터를 더 모으거나 다시 분류해도 이 스크립트만 재실행하면 대시보드가 최신 상태로 갱신됨
- "앞으로 알아갈 내용"(사람인 연동, 포트폴리오 추천 로직 등)은 아직 실제 데이터가 없는 계획
  단계라 `src/build_dashboard.py` 맨 위의 `ROADMAP_ITEMS` / `DONE_ITEMS` 리스트에 직접 적어서
  관리함 — 새 분석이 끝나면 항목을 `ROADMAP_ITEMS`에서 `DONE_ITEMS`로 옮기면 됨

## 5) Q&A 에이전트 (터미널 테스트용, 포트폴리오 프로젝트의 씨앗)

```powershell
python src\ask_agent.py
```

- 배경: 코딩 지식이 아직 없고(Python/SQL/C++ 등 미학습), 바이브코딩(AI 에이전트로 코드를 짜는 것) 경험만
  있는 상태에서 "데이터를 다루는 프로젝트"를 시작하려고 브레인스토밍한 결과, 이번 주 분석 결과를
  그대로 "채용시장 Q&A 에이전트"로 감싸는 방향으로 정함. 데이터가 이미 있어서 가장 빠르게
  시작할 수 있고, "동아리 친구들이 실제로 궁금해할 주제"라 유저를 모으기도 비교적 쉬움.
- 지금은 **LLM API 키가 없어서** 자연어 생성 없이, 키워드 매칭만으로 답하는 v1임
  (`DOMAIN_ALIASES`/`SKILL_KEYWORDS`/`OUTLOOK_KEYWORDS`로 업종·의도를 잡아냄).
  나중에 API 키가 생기면 `answer()` 함수 안에서 검색된 데이터 + 질문을 LLM에 넘겨
  자연스러운 문장으로 답하도록 바꿀 수 있음 (지금 구조는 그 확장을 염두에 두고 나눠둠).
