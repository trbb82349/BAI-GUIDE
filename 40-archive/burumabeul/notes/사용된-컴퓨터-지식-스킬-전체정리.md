# 사용된 컴퓨터 지식/스킬 — 전체정리

## 프로젝트 요약

브라우저에서 바로 열어 사람 한 명과 컴퓨터(NPC) 한 명이 즐기는 부루마블 보드게임을 만들었습니다. 설치나 서버 없이 `부루마블.html` 파일 하나만 더블클릭하면, 40칸 보드, 주사위 3D 애니메이션, 땅 구매·건물 짓기, 효과음까지 전부 그 파일 안에서 작동합니다.

## 사용한 지식/스킬

- **한 파일로 완결된 웹 프로그램 (HTML+CSS+JavaScript)**
  - 어디서 썼는지: `src/부루마블.html` 전체. 화면 모양(HTML), 디자인(CSS), 동작 방식(JavaScript)이 파일 하나에 다 들어있음
  - 어떤 효과가 있었는지: 서버를 따로 켜거나 프로그램을 설치할 필요 없이, 파일을 더블클릭만 하면 누구 컴퓨터에서든 바로 실행됩니다. 인터넷 없이도(폰트 제외) 게임이 돌아갑니다.

- **CSS 격자 배치 (Grid)**
  - 어디서 썼는지: 보드 40칸을 11×11 격자에 정확히 배치한 `.board` 스타일
  - 어떤 효과가 있었는지: 칸 하나하나의 위치를 일일이 좌표로 계산하지 않고, "몇 번째 줄, 몇 번째 칸"이라고 규칙만 정해주면 브라우저가 알아서 반듯하게 정렬해줍니다. 덕분에 위/아래 칸은 세로로 길고 좌/우 칸은 가로로 긴 모양도 쉽게 만들 수 있었습니다.

- **CSS로 그림 그리기 (이미지 파일 없이 국기 표현)**
  - 어디서 썼는지: `FLAG_CSS` 부분 — 색 그라디언트를 겹쳐서 국기 모양을 코드로 직접 그림
  - 어떤 효과가 있었는지: 국기 이미지 파일을 따로 준비하거나 인터넷에서 받아올 필요가 없어서, 어떤 환경에서도 항상 깨지지 않고 보입니다. 실제 이모지 국기가 일부 브라우저에서 안 보이는 문제를 이렇게 피해갔습니다.

- **CSS 3D 효과 (주사위 굴리기 애니메이션)**
  - 어디서 썼는지: `.cube`, `.face` 스타일과 `spinDice()` 함수 — 정육면체를 실제로 회전시켜 원하는 눈이 보이게 함
  - 어떤 효과가 있었는지: 평면 그림을 순서대로 바꿔치기하는 대신, 진짜 주사위처럼 입체적으로 굴러가는 느낌을 줍니다.

- **소리를 코드로 직접 만들기 (Web Audio API)**
  - 어디서 썼는지: `playTone()`, `playNoiseClick()`, `playDiceSound()`, `playCoinSound()` 함수들
  - 어떤 효과가 있었는지: mp3 같은 소리 파일을 따로 구하지 않아도, 브라우저가 그 자리에서 "삐-" 소리나 "달그락" 소리를 직접 합성해서 냅니다. 파일 용량도 없고, 저작권 문제도 없습니다.

- **순서를 기다리며 진행하기 (비동기 처리: async/await, Promise)**
  - 어디서 썼는지: 턴이 진행되는 전체 흐름 — 주사위 굴리기 → 이동 → 카드 창 뜸 → "확인" 누를 때까지 기다림 → 다음 단계로
  - 어떤 효과가 있었는지: "창이 떠 있는데 뒤에서 다음 턴이 먼저 진행되는" 것 같은 꼬임을 막아줍니다. 사람이 "확인"을 누르거나, NPC가 일정 시간을 기다린 뒤에야 다음 동작으로 넘어가도록 순서를 정확히 지킵니다.

- **화면을 통째로 다시 그리는 방식 (render 함수로 상태 갱신)**
  - 어디서 썼는지: `render()` 함수 — 돈, 위치, 보유 자산이 바뀔 때마다 이 함수를 호출해 화면 전체를 새로고침
  - 어떤 효과가 있었는지: "이 부분만 바꿔야지"라고 하나하나 신경 쓰지 않고, 게임 상태(누가 얼마 있고 어디 있는지)만 정확히 관리하면 화면은 항상 그 상태를 그대로 보여주게 만들었습니다. 실수로 화면과 실제 상태가 어긋나는 버그를 줄여줍니다.

- **컴퓨터 자동 플레이어 로직 (NPC 판단)**
  - 어디서 썼는지: NPC가 땅을 살지 말지, 건물을 지을지 판단하는 부분
  - 어떤 효과가 있었는지: 사람이 없어도 혼자서 2인용 게임을 테스트하고 즐길 수 있게 해줍니다.

- **자동 시뮬레이션으로 검증하기**
  - 어디서 썼는지: README에 적힌 대로, Node.js로 양쪽을 NPC로 돌려 무한 루프나 파산 처리가 제대로 되는지 자동으로 여러 판 돌려봄
  - 어떤 효과가 있었는지: 사람이 직접 수십 판을 플레이하며 눈으로 확인하지 않아도, 코드가 스스로 게임을 반복 실행해서 규칙에 오류가 없는지 빠르게 확인할 수 있었습니다.

- **외부 폰트 불러오기 (Google Fonts)**
  - 어디서 썼는지: `<link href="https://fonts.googleapis.com/...Jua...">` — 손글씨 느낌 폰트 하나 사용
  - 어떤 효과가 있었는지: 컴퓨터에 그 폰트가 없어도 인터넷에서 자동으로 받아와 예쁜 글씨체로 보여줍니다. 단, 인터넷이 없으면 기본 글씨체로 대체됩니다.

## 다음에 비슷한 작업을 할 때 해야 할 점

- 규칙이 복잡한 게임을 만들 때는, 먼저 규칙을 글로 정리한 문서(`notes/rules.md`)를 따로 만들어두면 나중에 "이게 원래 의도한 규칙이 맞나?"를 헷갈리지 않고 확인할 수 있다.
- 창(팝업)이 여러 번 연달아 뜨는 프로그램은, "확인을 눌러야 다음으로 넘어간다"는 규칙을 처음부터 통일해서 정해두면 나중에 꼬이지 않는다.
- 이미지나 소리 파일을 구하기 애매할 때는, 코드로 직접 그리거나(CSS) 합성하는(Web Audio) 방법도 있다는 걸 기억해두면 외부 자료 없이도 완성할 수 있다.
- 게임처럼 규칙이 많은 프로그램은 사람이 일일이 플레이해보기 전에, 컴퓨터로 자동 반복 실행(시뮬레이션)해서 큰 오류부터 걸러내면 시간을 아낄 수 있다.

## 다음에 비슷한 작업을 할 때 주의할 점

- 파일 하나에 모든 코드를 다 넣는 방식은 실행은 편하지만, 내용이 길어질수록(이 프로젝트는 1,400줄이 넘음) 원하는 부분을 찾기 어려워진다. 특정 기능을 찾을 때는 검색(Grep)으로 함수 이름을 먼저 찾는 게 빠르다.
- 소리는 브라우저 정책상 사용자가 버튼을 누르기 전까지는 자동으로 재생되지 않는다. "게임 시작" 같은 버튼을 누른 뒤에야 소리가 켜지도록 만들어야 한다.
- 인터넷 연결에 의존하는 부분(구글 폰트 등)은 연결이 없으면 다르게 보일 수 있다는 점을 문서에 미리 남겨둬야 나중에 "왜 글씨체가 다르지?" 하는 혼란을 막을 수 있다.
- 이 프로젝트는 사람이 실제 보드게임 사진을 보고 알려준 정보를 기반으로 재구성한 것이라, 원문(나무위키)을 직접 확인하지 못한 부분은 "자체적으로 정한 수치"라고 명확히 구분해서 남겨뒀다. 공식 자료를 못 볼 때는 이렇게 추정/각색한 부분을 표시해두는 게 나중에 오해를 막는다.
