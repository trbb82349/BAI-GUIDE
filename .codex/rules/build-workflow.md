# build-workflow.md — 작업 카드와 첫 결과물 생성 규칙

## 목표

새 작업은 작고 실행 가능해야 합니다. `/build`는 아이디어를 작업 카드로 줄인 뒤, 1시간 안에 눈으로 확인할 수 있는 첫 결과물까지 만드는 흐름입니다.

## 생성 위치

여러 파일로 구성되는 작업은 워크스페이스 루트의 `10-projects/작업이름/`에 만듭니다.

루트는 `AGENTS.md`, `README.md`, `.codex/`, `10-projects/`가 함께 있는 폴더입니다. 현재 위치가 `10-projects/` 안쪽이거나 다른 하위 폴더여도, 하위 폴더에 새 `10-projects/`를 만들지 않습니다.

폴더명은 가능하면 영문 소문자와 하이픈을 사용합니다.

```text
10-projects/
└── my-first-automation/
    ├── README.md
    ├── src/
    ├── input/
    ├── output/
    └── notes/
```

`30-resources/examples/`는 참고 예시 전용입니다. 새 사용자 작업은 `10-projects/` 바로 아래에 만들고, `30-resources/examples/` 안에는 만들지 않습니다.

## 사용된 컴퓨터 지식/스킬 노트 (notes/)

새 프로젝트를 만들 때든, 이전에 진행하던 프로젝트를 이어서 할 때든 동일하게 적용합니다. 작업을 진행하다가(새 기능 완성, 큰 진전 등) 이번에 처음 쓴 컴퓨터 지식·스킬이 있으면 `notes/` 폴더의 "사용된 컴퓨터 지식/스킬" 파일을 계속 업데이트합니다.

- 프로젝트에 해당 파일이 이미 있으면: 새로 쓰인 지식/스킬만 그 파일에 이어서 추가합니다. 이미 적혀 있는 항목은 다시 쓰지 않습니다.
- 아직 파일이 없으면: 새로 만듭니다.
- 컴퓨터 지식이 전혀 없는 사람 입장에서, 이번에 쓰인 지식·스킬이 어디서 어떤 효과를 냈는지, 다음에 비슷한 작업을 할 때 무엇을 하고 무엇을 조심해야 하는지를 쉬운 한글로 정리합니다.
- CSS, 렌더링, CSV처럼 전문 용어가 나오면 처음 등장할 때 옆에 괄호로 짧은 뜻을 바로 붙입니다.

형식은 `.codex/references/notes-learning-guide.md`를 따릅니다.

## 작업 카드

먼저 아래 5줄을 정리합니다.

```text
목표:
입력:
출력:
성공 기준:
오늘 만들 최소 버전:
```

정보가 부족하면 최대 4개까지만 묻고, 사용자가 모르겠다고 하면 안전한 기본값을 제안합니다.

## README 필수 내용

`README.md`는 소개 문서가 아니라 다음 세션에 바로 이어서 실행할 수 있는 작업 카드입니다.

- 작업 카드
- 만들 기능 체크리스트
- 실행 방법
- 확인 방법
- 다음에 Codex에게 요청할 말

작성 전 `.codex/references/work-readme-guide.md`를 읽고, 작성 후 `.codex/references/work-quality-checklist.md`로 점검합니다.

## 첫 결과물 기준

가능하면 빈 폴더와 README에서 끝내지 않습니다. 아래 중 하나 이상을 만듭니다.

- Python 스크립트 1개
- 샘플 입력 파일 1개
- 결과 Markdown/CSV/HTML 1개

## 크기 조절

아이디어가 크면 로컬 파일 하나 또는 예시 데이터 하나로 실행되는 최소 버전으로 줄입니다.

예:

- "생활 관리 앱" → "CSV를 읽어 오늘 할 일 Markdown 만들기"
- "유튜브 정리 도구" → "자막 txt를 요약 노트로 바꾸기"
- "포트폴리오 사이트" → "작업 1개를 소개하는 정적 HTML 만들기"

## 기본 기술 선택

초기 작업은 아래 순서로 단순한 도구를 우선합니다.

1. Markdown 정리
2. Python 로컬 스크립트
3. CSV/Excel 처리
4. HTML/CSS 정적 페이지
5. 웹 스크래핑
6. 외부 API 또는 배포

외부 API, 로그인 자동화, 결제/개인정보 처리, 배포는 기본안으로 잡지 않습니다.
