# notes-learning-guide.md — 사용된 컴퓨터 지식/스킬 노트 작성 기준

`10-projects/작업이름/notes/` 폴더에는 일반 작업 메모 외에 **사용된 컴퓨터 지식/스킬** md 파일을 둡니다. 새 프로젝트를 시작할 때든 예전 프로젝트를 이어서 할 때든, 작업을 진행하다가(새 기능을 만들거나 큰 진전이 있을 때마다) 이번에 처음 쓴 지식·스킬이 있으면 이 파일을 계속 업데이트합니다.

## 새로 만들지 vs 업데이트할지

1. 작업을 시작하기 전에 `notes/` 안에 "사용된 컴퓨터 지식/스킬" 파일이 이미 있는지 먼저 확인합니다.
2. 있으면: 그 파일의 "사용한 지식/스킬" 항목 아래에 이번에 새로 쓴 지식·스킬만 이어서 추가합니다. 이미 적힌 항목은 그대로 두고 중복 작성하지 않습니다.
3. 없으면: 새로 만듭니다.
4. 프로젝트 성격이 완전히 달라 별도 문서로 분리하는 게 더 명확할 때만 새 파일을 추가로 만듭니다.

## 대상 독자

컴퓨터 지식이나 개발 스킬을 전혀 모르는 사람. 전문 용어는 쓰지 않거나, 쓰더라도 바로 쉬운 말로 풀어서 설명합니다.

## 파일명

`notes/사용된-컴퓨터-지식-스킬-전체정리.md` (날짜 없이. 워크스페이스 공통 파일명 규칙의 예외입니다). 프로젝트 성격이 완전히 달라 별도 문서로 분리할 때만 `짧은주제` 부분을 다른 말로 바꿔 새 파일을 만듭니다.

## 분량 원칙 (중요)

이 파일은 **전체 70줄을 넘기지 않습니다.** 진행 과정·시행착오의 자세한 서술은 같은 프로젝트의 `README.md`에 이미 있으므로 여기서 반복하지 않습니다. 이 파일의 역할은 "무엇을 배웠는지"를 나중에 다른 프로젝트에서도 빠르게 떠올릴 수 있는 용어 사전에 가깝습니다.

- **프로젝트 요약**: 2~3줄로 짧게. 무엇을 만들었는지만 적고, 어떤 시행착오를 거쳤는지는 적지 않습니다(README.md를 보라고 생각하면 됩니다).
- **사용한 지식/스킬**: 각 항목은 "용어 (쉬운 말 설명): 무엇이고 왜/어디에 썼는지"를 1~2줄로 끝냅니다. "어디서 썼는지"·"어떤 효과가 있었는지"를 별도 하위 항목으로 나누지 않습니다.
- 업데이트할 때 항목이 늘어나서 70줄을 넘기게 되면, 새 항목을 우선하고 오래되었거나 이후 다른 방식으로 대체된 항목(예: 나중에 다른 기술로 교체된 초기 버전 내용)은 정리해서 줄을 확보합니다.

## 필수 섹션

```markdown
# 사용된 컴퓨터 지식/스킬 — (짧은 주제)

## 프로젝트 요약
(2~3줄. 자세한 진행 과정은 이 프로젝트의 README.md 참고)

## 사용한 지식/스킬
- 용어/개념 (쉬운 말 설명): 무엇이고 왜/어디에 썼는지 1~2줄
(스킬이 여러 개면 항목을 반복. 업데이트할 때는 새로 쓰인 항목만 아래에 이어서 추가)

## 다음에 비슷한 작업을 할 때 해야 할 점
-

## 다음에 비슷한 작업을 할 때 주의할 점
-
```

## 작성 기준

- 코드 자체를 설명하지 말고, 코드가 하는 일을 비유나 일상 언어로 짧게 설명합니다. (예: "API"는 "다른 프로그램에 정보를 물어보는 창구" 같은 식)
- 전문 용어(영어 약어, 프로그램·도구 이름, 파일 형식, 기술 이름 등)는 문서 안에서 처음 나올 때 옆에 괄호로 짧은 뜻을 바로 붙입니다. 뒤에서 같은 용어를 또 쓸 때는 매번 반복하지 않아도 됩니다. (예: CSS(웹페이지 색깔·글씨체·배치를 꾸미는 코드), 렌더링(코드나 데이터를 실제 화면에 그리는 것), CSV(엑셀처럼 표 데이터를 저장하는 단순한 파일 형식))
- 크게 실패했거나 반복하면 안 되는 시행착오만 "주의할 점"에 한 줄로 남깁니다. 자세한 경위는 README.md에 맡깁니다.
- 기본적으로 파일을 새로 만들지 말고 기존 파일을 업데이트합니다. 70줄 한도 안에서 "해야 할 점"·"주의할 점"도 새로 배운 내용이 있으면 함께 덧붙입니다.
