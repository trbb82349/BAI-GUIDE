## 실행 관찰 기록

**테스트 시나리오**: "친구들이랑 보려고 사이트 하나 만들고 싶어. 요즘 핫한 유튜브 쇼츠 트렌드를 매일 보여주는 페이지였으면 좋겠어. 만들어줘." — 일부러 데이터 원천·인증 여부·GitHub 계정 여부를 안 밝히고, YouTube Data API처럼 스킬의 "무료 한도" 표에 없는 서비스가 필요한 케이스로 설계.

**정상 작동한 기준**:
- **Input**: 5개 확인 항목을 사용자 메시지와 대조해 "이미 답 나온 것(주제, 주기)"과 "안 나온 것(데이터 원천, GitHub 계정, 인증)"을 구분해 실제로 질문함. Steps로 바로 안 넘어감.
- **Judgment**: 무료 한도 표에 없는 YouTube Data API를 만나자 "무료일 것"이라고 지어내지 않고 "확인 필요"로 처리 (제약 1 적용). 스크래핑 옵션을 언급하면서 이용약관 확인 전엔 로직을 완성하지 않는다는 `[OPEN: ...]` 규칙도 그대로 적용됨.

**무너진 지점**: "핫한 트렌드"를 무슨 기준(조회수순? 최신순? 특정 키워드?)으로 고를지가 Input 5개 항목 어디에도 명시돼 있지 않아서, 서브에이전트가 이 부분만 스스로 판단해 조용히 범위를 좁힘(질문하지 않고 넘어감) — 서브에이전트 스스로도 관찰 메모에서 "스킬 밖에서 임의로 범위를 좁힌 부분"이라고 인정함. 미션 설명이 예고한 대로 Judgment(정확히는 Input의 판단 재료 부족)에서 무너짐.

**조치**: Input 1번 항목에 "선별이 필요한 주제라면 기준도 같이 확정, 없으면 질문" 문구를 추가해 본문 보강. 파일 분리는 하지 않음(4단계 지시대로).

## 성공 기준 자가 점검

- ① description만 보고 언제 발동할지 알 수 있는가 → Yes. 트리거 문구가 구체적으로 나열돼 있고, "명시 요청 없어도 먼저 사용한다"까지 명시.
